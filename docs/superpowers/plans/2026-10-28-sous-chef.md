# Sous Chef Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Sous Chef Android app: share a recipe URL from a browser, parse it on-device with Python, save it to a local library, cook from four tabs, edit imported recipes, and shop from one shared list.

**Architecture:** Single `:app` module. OkHttp fetches HTML; Chaquopy runs `recipe-scrapers` plus a JSON-LD fallback in Python and returns normalized JSON. Kotlin owns models, persistence (DataStore JSON), navigation and a Compose Material 3 UI. No server, no account, no analytics.

**Tech Stack:** Kotlin, Jetpack Compose Material 3, Navigation Compose, DataStore, kotlinx.serialization, OkHttp 4.12.0, Coil 2.7.0, Chaquopy 17.2.0, Python 3.13, recipe-scrapers 15.13.0, pytest.

**Spec:** `docs/superpowers/specs/2026-10-28-sous-chef-design.md`

## Global Constraints

- minSdk 33; compileSdk 36; targetSdk 36; AGP 9.4.1; Gradle wrapper 9.8.2; JDK 25 on this machine.
- Kotlin/Compose plugin 2.3.21. Do **not** apply `org.jetbrains.kotlin.android`; AGP 9 has built-in Kotlin.

- App id/namespace `com.souschef.app`; versionName 0.1.0.
- All HTML parsing happens in Python. Kotlin never parses HTML.
- No Hilt, no Room, no Firebase, no analytics, no network calls except fetching the shared page and recipe images.
- Every user-visible string lives in `res/values/strings.xml`; copy must match the spec exactly.
- Palette: paper `#FAF5EB` / `#171310`, surface `#FFFDF8` / `#201B17`, ink `#211C18` / `#F2E9DC`, muted `#6B5F55` / `#B3A697`, terracotta `#B4442A` / `#E48263`, wash `#F3DDD4` / `#3A241D`, rule `#E4D9C8` / `#3A312A`, sage `#5A6650` / `#93A487`, error `#A33A2B` / `#F08A76`.

- Commit after every task with the message given in that task.

## Review Focus

These are the five inputs most likely to break a real cook's session. Each has a test in the task that owns the code.

1. Share text with no URL, several URLs, or trailing punctuation — must not fetch garbage; show "That share didn't include a link." (Task 3, Task 7).
2. A redirect to a 404, a PDF, or a page over 8 MB — must fail with copy, never hang, crash or OOM (Task 5).
3. Re-sharing a recipe already in the library — must open the saved copy and create no duplicate (Task 7).
4. Ticking steps/ingredients, then editing or reordering lines — ticks must stay on their own text (Task 4, Task 11).
5. Recipes missing times, temperatures, servings or images — UI shows "—"/hides sections and never crashes (Task 2, Task 10).

- [ ] **Step 3: Implement the extractor**

`extract.py` responsibilities, in order:
1. try `recipe_scrapers.scrape_html(html, org_url=url)` with supported fields (`title`, `ingredients`, `instructions`, `prep_time`, `cook_time`, `total_time`, `image`, `author`, `site_name`, `yields`);
2. otherwise parse all `script[type="application/ld+json"]` blocks with `bs4` + stdlib `json`, walking `@graph`, top-level arrays, `Recipe`/`HowToStep`/`HowToSection`, ISO 8601 durations via regex;

`missing` lists `author`, `imageUrl`, `servings`, `prepMinutes`, `cookMinutes` and `totalMinutes` when they come back null. A single instruction string is split on newlines, with leading numbering stripped only when every line is numbered.

Temperature regexes live in one module-level helper used by both functions; degree-less values require a `C`/`F` token; `gas mark 4` maps to 180°C; conversions round; duplicates collapse by Celsius value keeping the first.
